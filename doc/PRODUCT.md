# 产品说明

CaretLex 是面向英文 Markdown 阅读的本地桌面应用，使用简体中文界面。选词后可以自动获取来源数据，也可以完整手填；用户检查最终 JSON 并确认 lemma 后，正文引用和词条定义写入同一 Markdown 文件。

## 阅读与录入

阅读器支持标题、段落、强调、列表、引用、GFM 表格、普通脚注、图片和代码高亮。原始 HTML 显示为源码文本。选区必须是同一个可映射普通文本节点中的完整英文单词，可含内部 ASCII 撇号或连字符；代码、链接、脚注定义和跨节点选区不提供存词入口。

点击“存为词条”后，本地 article 服务提取真实词形和原句，在真实选中位置添加 `[]`，例如 `She [went] home.`。标记不插入正文。软换行保留，显式硬换行分段；英文缩写、小数、闭合引号、直接报告语和省略号按声明的规则分句。提取失败时明确提示，停止依赖原句的 AI 请求，保留手动编辑。

默认词条结构：

```json
{
  "lemma": "go",
  "contexts": [
    {
      "original_sentence": "She [went] home.",
      "meaning_in_context": "（动词）去",
      "english_definition": "to move or travel"
    }
  ],
  "other_meanings": []
}
```

同一 lemma 共用一条脚注。自动合并仅按完整标记原句向 contexts 追加新项；同 key 保留已有人工释义，其他根字段和 other_meanings 保留。相同句子中不同位置的 bank 具有不同 key；两个正文位置的相同标记原句共用同一 context。

lemma 从选词小写形式开始，只是待确认建议；AI 可提供原型建议，本地校验不能验证语义。首次确认保存后身份锁定，失败重试也保持锁定。已经引用的词条直接绑定保存身份。默认结构的根级 lemma 不能更改或删除；应用没有全篇词条重命名操作。

## Provider 与设置

首次启动为 `providers: []`，可纯手动保存。article 是固定本地来源，不计入启用数量。自动 provider 的 type 标识实现，name 标识可配置实例，同 type 可有多个 name；一次最多启用一个实例，也可以全部停用。

LLM 表单提供实例名称、类型、启用状态、API 类型、Base URL、模型、本机 Key、Prompt、响应 JSON 示例、JSON mode、超时和最大输出 tokens。已有 Key 以实例名称加掩码（前 5 位与后 4 位）和删除按钮显示；删除会移除本机凭据条目并清空草稿引用，保存设置后生效。实例可折叠，启用与删除按钮位于标题栏。连接参数分栏，Prompt 与响应示例使用大尺寸可调整文本框，窄屏自动纵向排列；保存按钮保持可见。表单启用会停用其他实例，并在默认保存结构和响应示例兼容时完整生成实际 name 的保存预设。自定义保存结构、缺失字段、类型变化或没有可靠预设时保留模板并提示原因，不猜测字段关系。

设置页展示通用设置与 Provider 实例表单，来源侧响应示例可编辑。保存映射通过设置文件中的 `saveTemplate` 配置。表单重命名更新模板中的明确来源引用，保留 `$literal` 内容。直接修改设置文件不自动应用预设；多个实例启用会报错。草稿只有成功保存后才参与自动请求。

自动获取发生在新增录入窗打开后，仅请求已保存、启用且被模板引用的实例。`type` 为 `LLM`，API 类型选择实际决定请求及响应协议：OpenAI Chat Completions、OpenAI Responses、Anthropic Messages 或 Gemini Generate Content。基础地址保留路径且不补版本路径，根据所选 API 追加相应端点。JSON mode 由服务支持；Anthropic Messages 通过 Prompt 请求 JSON，不提供 json_object 开关。请求内容就是设置页展示的 Prompt 替换变量后的结果，应用不追加任何隐藏指令或 system 文本；与旧默认完全一致的 Prompt 在加载时升级为新默认。所有协议只接受纯 JSON 内容，不剥离围栏、不抽取片段、不修补、不自动重试或降级。响应示例检查字段及类型，合法字段参与映射，缺失或错误字段待手填。

## 手改与失败

录入窗始终编辑完整最终 JSON。没有 provider、请求失败、字段缺失或映射失败时，都可独立提交合法人工稿。

草稿未手改时自动结果进入映射与合并；有手改稿时，新结果作为待应用 JSON 展示，用户明确应用才替换草稿。手动重试也保留手改稿。关闭录入或切换标签取消旧请求并忽略旧结果；标签切换保留内存草稿。设置变化取消旧获取，保留草稿，新请求使用新保存配置。文档外部变化使旧选区会话失效，稿件仍可检查和复制。

保存期间禁止重复提交。文件对话框取消、revision 冲突和写入失败保留稿件与错误；只有主进程完成文件写入后才结束录入。未保存词条草稿只在内存中，关闭标签或窗口会提示返回编辑或放弃。

## 已保存词条

悬停或聚焦词形时，仅读取 Markdown 和本地 article，按完整标记原句定位 context，不请求 AI。卡片以正文样式显示当前上下文的词性与中文释义，释义为空时提示可编辑补全；全部 contexts、other_meanings 与完整 JSON 仍可展开查看。

没有匹配、多个匹配或自定义结构无法识别时明确提示，不任意选择第一项。正文修改不会改写历史原句。编辑捕获开始编辑时的文档身份和 revision，保存等待真实回执；失败保留文本。区块外词条只读。删除移除托管定义及全部真实正文引用，保留原文词形。

## 本机文件与边界

设置为 UTF-8 JSON，根字段为 `theme`、`providers` 和 `saveTemplate`，可放在同步目录。无法解析时显示错误与设置文件路径，可修复该文件，或点击“恢复默认设置”写入默认配置。恢复会替换当前设置和设置草稿，清空 provider 实例，并保留本机凭据文件；文件或路径在加载后变化时拒绝覆盖。无法解码、超限或损坏的路径指针也可通过显式恢复操作修复。读取不会自动替换损坏字节。旧脚注保留通用 JSON 阅读能力，不自动转换为 contexts。

Key 存在本机用户数据目录的独立明文 `credentials.json`，权限 `0600`；设置只含稳定引用。新 Key 先写本机文件，再进入设置草稿；设置失败不改变旧有效引用。损坏凭据文件不会被空文件替换。有引用但本机缺失时明确失败，无引用才匿名请求。设置表单只显示掩码，完整 Key 不进入渲染进程；删除按钮移除本机条目并在草稿中清空引用。设置位置选择禁止使用凭据文件和本机路径指针。

Markdown 上限 16 MiB，设置、单词条及 AI 请求/响应各为 1 MiB，超限失败，不截断。自定义结构由用户维护，应用不做语义字段匹配、通用摘要识别或累计路径推断。分句按规则验收，不承诺通用语义分句；AI 输出需人工检查。

源码使用 CodeMirror，保存前比较文件 revision，原子写入保留 BOM 和未触及正文。导出只包含当前文档托管词条。应用不维护账户、独立词条数据库、学习状态或复习计划。Linux x64 提供 AppImage 和 deb；窗口使用品牌图标，启动时在用户 XDG 数据目录写入不显示于启动菜单的桌面条目，使任务栏按 app_id 匹配图标；本地图片限文档目录及子目录，远程图片由用户主动加载。
