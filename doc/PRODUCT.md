# 产品说明

本文描述 CaretLex 当前提供的产品能力和边界。文件格式以[文件协议](PROTOCOL.md)为准，实现结构见[架构说明](ARCHITECTURE.md)。

## 产品定位

CaretLex 是面向英语学习者的本地 Markdown 阅读应用，界面语言为简体中文。用户在阅读正文时选择生词，手动确认 lemma 和释义；正文引用与完整词条值保存在同一个 Markdown 文件中。

适用场景是使用文本编辑器、笔记工具或 Git 管理英文 Markdown，并希望词条能够随文件复制、同步和比较。CaretLex 同时提供源码编辑器，但不承担通用所见即所得 Markdown 编辑器的功能。

## 阅读与存词

应用可以新建文档，或打开 `.md`、`.markdown` 和 `.mdown` 文件。阅读视图支持：

- 标题、段落、强调、加粗、删除线、列表、任务列表、引用和分隔线；
- GFM 表格与普通脚注；
- 行内代码和代码块，代码块对内置语言集合使用 Shiki 高亮；
- 本地相对图片，以及由用户主动触发加载的 HTTP/HTTPS 远程图片；
- 由系统处理的 HTTP、HTTPS 和 mailto 外部链接；
- Markdown 原始 HTML 的源码文本显示。

存词入口只接受同一个可映射文本节点中的完整英文单词。单词首尾必须是 ASCII 英文字母，内部可以包含 ASCII 撇号或连字符。代码、链接、原始 HTML、脚注定义、多词选区、跨节点选区和无法唯一映射到源码的选区没有存词入口。

录入卡默认提供 lemma、中文翻译和英文例句。lemma 从选中词形的小写形式开始，由用户确认；应用不执行自动词形还原。默认词条值为：

```json
{"word":"go","translation":"去","example":"She went home."}
```

设置可以把词条模板改为任意 JSON 值，并用 JSON Pointer 将选中词形、lemma、句子、手动输入或常量绑定到模板位置。

## 词条交互

- 新 lemma 在选中词形后添加 `[^w-lemma]`，并在文末托管区块创建定义。
- 文档中已有托管定义时，新位置只增加引用，定义值保持不变。
- 同一位置已有相同引用时不产生文件变化；已有另一条词条引用时拒绝叠加。
- 有效词条在阅读视图中以虚线下划线标记，悬停约 300 ms 或键盘聚焦后显示词条卡。
- 词条卡显示 lemma、可识别的 `translation` 和 `example`，并始终提供完整 JSON 查看。
- 托管词条可以编辑完整 JSON 值。删除操作移除定义及其全部真实正文引用，保留原文词形。
- 托管区块外的合法词条可以阅读，但不能通过词条卡编辑或删除。

损坏的托管区块、重复定义和其他阻断诊断会关闭存词与导出入口。源码模式仍可用于查看和修复文件。

## 文档编辑与冲突

工作区使用标签页管理打开的文档。相同真实路径只对应一个文档会话。每个标签可以在阅读模式和 CodeMirror 源码模式之间切换。

源码修改保存在标签草稿中，保存按钮或 `Mod-S` 才写入磁盘。带有未保存草稿的标签在切回阅读、关闭标签或关闭窗口时显示“保存、放弃、取消”选择。文档有外部修改时：

- 没有本地草稿的标签加载磁盘内容并重新解析；
- 有本地草稿的标签保留草稿并显示冲突；
- 使用旧 revision 的保存和词条操作被主进程拒绝。

## 设置与导出

设置页包含主题选择和完整设置 JSON 编辑器。设置文件位于 Electron 用户数据目录，或位于用户通过“更改位置”选择的同步路径；本机用户数据目录只保存同步文件的绝对路径指针。外部修改使用 revision 检查，设置草稿不会覆盖新的磁盘版本。

“导出 JSON”只导出当前文档有效托管区块中的词条。结果是 UTF-8 单行 JSON 对象，键为按 ASCII 字典序排列的 lemma，值为定义中的完整 JSON 值。区块外词条、普通脚注和其他文档不参与导出。

## 功能边界

应用只提供手动 provider，不连接词典服务，不维护账户、词条数据库、学习状态、添加次数或复习计划。阅读选词只处理英文单词，不处理短语或其他语言的分词。相对 Markdown 链接保持不可点击；本地图片限制在 Markdown 文件所在目录及其子目录内。打包配置只包含 Linux x64 AppImage 和 deb。
