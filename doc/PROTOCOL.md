# CaretLex 文档与设置协议

> 状态：首版共享核心按本协议实现。本文仍是词条、设置和导出的权威文件格式；应用与发行验收状态见 [路线图](ROADMAP.md)。项目入口见 [项目概览](OVERVIEW.md)，交互见 [产品说明](PRODUCT.md)，模块和文件写入见 [架构说明](ARCHITECTURE.md)。

## 1. 基本约束与术语

CaretLex 阅读英文 Markdown，界面使用简体中文。词条数据属于用户的 `.md` 文件，不另建词条数据库。设置属于用户可同步的 UTF-8 JSON 文本文件。文档可以在其他 Markdown 工具中继续打开。

| 术语 | 含义 |
|---|---|
| 原文词形 | 阅读时实际出现的文字，例如 `went`；存词不得改变它。 |
| lemma | 用户确认的词条身份，例如 `go`；同一文档内相同 lemma 共享一条定义。 |
| 词条引用 | 正文中的 `[^w-lemma]`，紧跟对应原文词形。 |
| 词条定义 | 与引用同标签的单行 JSON 脚注定义。JSON **值**可以是任何合法根类型。 |
| 托管区块 | 由两条专用 HTML 注释围住的文末词条定义集合；只有此处的定义允许应用增删改。 |
| 区块外词条 | 托管区块外的合法词条定义；允许阅读，不由应用迁移、编辑或删除。 |

本协议的词条标签用连字符 `w-`，不用早期草案中的 `w:`。后者在 GitHub 的 cmark-gfm 中有过含冒号脚注链接缺失的[公开问题](https://github.com/github/cmark-gfm/issues/250)。这只是格式选型依据，不代表外部渲染器会实现 CaretLex 的悬停卡。

## 2. Markdown 语法

### 2.1 标签与引用

词条标签的完整、大小写敏感规则为：

```regex
^w-([a-z]+(?:['-][a-z]+)*)$
```

括号捕获部分是 lemma。它必须已经是小写 ASCII 英文字母，可在字母之间包含 ASCII 撇号 `'` 或连字符 `-`。数字、空格、前后或连续分隔符、排印撇号 `’`、大写字母都不属于首版 lemma。应用预填选中词形，用户可在保存前修改并确认 lemma；不自动把 `went` 推断为 `go`。选择的原文必须是一个词，短语或句子只可查看选区，不能存为词条。

引用写在原文词形后：`went[^w-go]`。多处可写同一标签，如 `went[^w-go]`、`goes[^w-go]`。引用是否存在，应按 Markdown 语法树中的真实脚注引用判断；代码块、转义后的字面文本等不能靠字符串搜索误认作引用。已在该位置附有相同标签时再次存词为无操作。若同一词位置已经附有另一条 `w-` 词条引用，不叠加第二条，提示用户先处理现有引用；普通脚注不因此删除。

### 2.2 定义与分类

词条定义在一条物理行内，形式为：

```markdown
[^w-go]: {"word":"go","translation":"去","example":"She went to school."}
```

对一个脚注的分类必须同时满足：

1. 标签严格匹配上述 `w-lemma` 规则；
2. 存在**唯一**的同标签定义，定义体在冒号后的同一物理行内；
3. 去掉定义体首尾水平空白后，整段恰好能由 `JSON.parse` 解析为一个 JSON 值，没有 Markdown、注释或其他尾随文本；定义没有续行。

三项都满足才作为词条显示：正文原文词形下方用中性虚线，词条脚注编号和文末定义不在 CaretLex 阅读视图显示，悬停显示该 JSON 值的可用摘要与完整值。其他脚注交给普通 GFM 脚注渲染；前缀相似、定义缺失、JSON 损坏都不能吞掉原文或影响别的普通脚注。普通脚注保留上标和文末列表。`remark-gfm` 明确支持 GFM 脚注，具体兼容行为仍须按[路线图的验证项](ROADMAP.md)实测；[其官方说明](https://github.com/remarkjs/remark-gfm)是本语法基线的参考。

JSON 根值允许对象、数组、字符串、数字、布尔值和 `null`。例如 `[^w-go]: null` 在本协议内是合法词条，标签 `go` 仍是身份。**不要求**任意 JSON 对象含有 `word`、`translation` 或别的固定键；对象中的 `word` 即使与标签不同，也不改变身份。UI 对没有默认摘要字段的值提供原始 JSON 查看，不猜测字段含义。

默认新建词条是特例：按固定顺序生成 `word`、`translation`、`example` 三个字符串字段。`word` 为确认后的 lemma，`translation` 为用户输入的非空中文翻译，`example` 为取到的当前英文句子或空字符串，允许用户在保存前修改。该默认结构不反向约束用户模板和既有词条。

### 2.3 托管区块

两个标记各占一整行，内容严格如下，且必须作为顶层 Markdown HTML 注释出现，不能位于代码块、引文或其他嵌套结构中：

```markdown
<!-- caretlex:vocab:start -->
<!-- caretlex:vocab:end -->
```

每篇文档至多有一对标记，起始标记在结束标记之前，结束标记后只允许空白；因此托管区块处于文末。有效区块内部只能有空行和符合上节形式的 `w-` 单行定义。应用首次存词时如无区块，就在文末创建一对标记；原文已有其他脚注时保持它们不变。区块为空时仍保留标记，后续可以继续添加词条。

每次应用写入时，从**当前磁盘内容**重建托管索引，按 lemma 的 ASCII 字典序输出定义，每个 lemma 一行。定义体使用 `JSON.stringify` 生成，禁止手工拼 JSON；对象键顺序以当前解析值的键顺序为准，默认新建值使用上述固定三字段顺序。应用可在词条写入时规范化托管区块内有效定义的排序和 JSON 空白，但必须保留每条 JSON 的语义值、不得丢弃不认识的行。区块外所有未触及原文字节、换行风格与 BOM 不因词条操作而变化。源码编辑模式中的用户主动修改另行处理。

### 2.4 完整示例

```markdown
# A short trip

She went[^w-go] to school. He goes[^w-go] home.
A note[^1] stays an ordinary footnote.

[^1]: This is a normal note.

<!-- caretlex:vocab:start -->
[^w-go]: {"word":"go","translation":"去","example":"She went to school."}
<!-- caretlex:vocab:end -->
```

本例两个引用共用一个定义。普通脚注 `[^1]` 仍在文末展示。文件脱离 CaretLex 时，支持 GFM 脚注的阅读器通常将 `[^w-go]` 当普通脚注，出现可点击编号和文末 JSON；这是预期的可读降级，CaretLex 专属的虚线和悬停卡不随纯文本自动迁移。[micromark 的 GFM 脚注扩展说明](https://github.com/micromark/micromark-extension-gfm-footnote)展示了标准脚注的编号、正文定义和回链输出。

## 3. 解析、诊断与可写性

打开文档时先解析 Markdown，收集真实脚注定义和引用的源码范围，再识别顶层托管标记和词条。重复定义检测还须检查原始源码，不能只看可能已经丢弃后续定义的 AST；GFM 脚注实现会将归一化后同名的重复定义优先匹配第一条，见 [micromark 官方说明](https://github.com/micromark/micromark-extension-gfm-footnote#syntax)。与候选 `w-` 标签经 GFM 标识符归一化后相同的定义也算冲突，例如大小写变体，不能据首条默选词条。内存 `Map<lemma, entry>` 只是由文件重建的临时索引，不作为持久数据源。不得依据渲染后的 DOM 文字偏移或原文子串首次出现位置猜测写入点；选区到源码范围必须能精确验证，验证失败时禁用存词并解释原因。文件实际写入的并发与原子性见[架构说明](ARCHITECTURE.md)。

| 情况 | 阅读显示与诊断 | 词条写入／导出 |
|---|---|---|
| 标签不匹配，例如 `[^w:go]` 或 `[^w-Go]` | 普通脚注。 | 不作为词条处理。 |
| 区块外 `w-` 定义是合法单行 JSON | 可显示词条，标记为“区块外，只读”。 | 不编辑、删除或迁入该定义；同 lemma 的新存词也拒绝，避免制造重定义。其他托管词条可正常处理。 |
| 区块外 `w-` 定义 JSON 无效 | 按普通脚注显示，给出非阻塞诊断。 | 不自动修复该行。若用户要以同 lemma 存词，须先在源码中处理原定义。 |
| 托管区块内某行 JSON 无效或出现未知非空内容 | 无效定义按普通脚注显示；列出行号和原因。 | 视为受损区块：拒绝本文件词条写入和导出，直到用户在源码模式修复。不得规范化时丢掉该行。 |
| 同一 `w-` 标签有多处定义，无论位于何处 | 提示所有位置；不选一条作为词条来源，引用按普通脚注降级。 | 拒绝本文件词条写入和导出，直到去重。 |
| 标记缺失一端、重复、逆序、嵌套，或结束标记后有非空白内容 | 保留全部原文，提示结构错误。 | 拒绝本文件词条写入和导出，直到修复。 |
| 没有托管标记且无冲突 | 按普通 Markdown 阅读。 | 首次存词创建区块；导出 `{}`。 |
| 有效区块中定义未排序、JSON 有多余空格 | 按实际值阅读。 | 下次用户触发词条写入时按规范重排，保留语义；单纯打开文件不改盘。 |

“拒绝词条写入”仅指应用的存词、词条编辑和词条删除；用户仍可在源码模式手动修复文件。诊断不能成为自动删除用户内容的理由。JSON 定义体的无效与区块结构受损分开处理：区块外的坏 JSON 是普通脚注，区块内的坏 JSON 同时使托管数据无法安全重排。

## 4. 存词、编辑、删除

1. 用户选中一个可精确定位的英文单词，确认 lemma 和默认翻译／自定义 JSON。应用读取当前文档并检查托管结构、重定义与磁盘版本。选区已失效时停止。
2. 若该 lemma 已在有效托管区块中，仅在新位置插入 `[^w-lemma]`；定义值、原句不自动改写，不维护 `count`。若当前位置已有同一引用，则文件完全不变。若 lemma 只存在于区块外，拒绝写入并指向该定义。
3. 若 lemma 不存在，在选中词形后插入引用，并在托管区块新增单行 JSON 定义；无区块时先创建。应用只改目标引用范围和托管区块，不重新序列化整篇 Markdown。
4. 显式编辑仅允许有效托管词条：以用户确认的**完整** JSON 值替换该定义体，经 `JSON.stringify` 写回。编辑值不改变标签身份；改 lemma 属于另一次明确的重命名操作，首版不提供自动重命名。
5. 删除有效托管词条时，从语法树找到正文中所有真实的同标签引用，删除引用 token，保留 `went`、`goes` 等原文词形；再移除托管定义。不得用全局字符串替换碰到代码样例或转义文本。区块外词条没有删除入口。

每一步只在能验证源码补丁范围、磁盘版本与结果解析状态时保存。冲突时保留当前草稿并提示处理，不覆盖外部编辑。文件保存采用同目录临时文件再原子替换；文档仍是唯一词条持久存储。

## 5. 可同步设置文件

设置页管理一个可阅读、可版本控制的 UTF-8 JSON 文件。默认文件放在应用配置目录；用户可将它迁移到指定同步路径。本机配置仅保留启动时找到该设置文件所需的路径指针。设置文件不包含缓存、词条索引或密钥。首版 `providers` 固定为 `manual`，保留数组结构仅为将来扩展接口，不能据此声称已有联网词典。

默认设置的协议形状如下：

```json
{
  "version": 1,
  "theme": "system",
  "providers": ["manual"],
  "entryTemplate": {"word": "", "translation": "", "example": ""},
  "bindings": {
    "/word": {"from": "lemma"},
    "/translation": {"from": "manual", "label": "中文翻译", "required": true},
    "/example": {"from": "sentence"}
  }
}
```

`theme` 为 `system`、`light` 或 `dark`。`entryTemplate` 是任意 JSON 值。`bindings` 的键是指向模板中**已存在**位置的 [JSON Pointer](https://www.rfc-editor.org/rfc/rfc6901)；空字符串 `""` 可指整个根值。来源 `from` 只能是 `selected`（所选原文词形）、`lemma`（用户确认的身份）、`sentence`（取到且可编辑的英文原句）、`manual`（录入卡手填）或 `constant`（绑定项自己的 `value`）。`manual` 可设 `label` 与 `required`；`constant` 必须有 JSON `value`。不允许失效指针或祖先／子孙重叠绑定，避免应用顺序决定结果；其他来源不执行用户代码或远程请求。

设置页先对文件整体 JSON、版本、枚举、指针与绑定做校验，再生效；无效设置保留原文件并显示具体错误，不用默认设置覆盖。默认三字段模板使用简洁录入表单并要求翻译非空。用户自定义模板可以通过原始 JSON 编辑；模板实例化后仍须是一份合法 JSON，保存前由用户确认。自定义根值例如字符串或 `null` 都可存入定义。设置修改不批量迁移或重新解释已写入文档的词条；旧值可继续以原始 JSON 查看。模板与绑定只决定**新建及显式编辑**的值。

手动 provider 的完成结果必须区分取消与合法的 JSON `null`：接口返回 `{kind: "value", value: JsonValue}` 或 `{kind: "cancelled"}`，不能以 `null` 作为取消哨兵。此规则也适用于将来的其他 provider。

## 6. 当前文档 JSON 导出

首版只导出当前文档**有效托管区块**中的词条；区块外只读词条不参与。输出是一个**单行** UTF-8 JSON 对象：键按 lemma ASCII 字典序，值为各定义的完整 `JsonValue`，不丢字段、不生成新 schema、不扫描文件夹。编码内容由 `JSON.stringify` 产生，文件扩展名为 `.json`。无区块或空区块导出 `{}`；文档存在第 3 节的阻断诊断时拒绝导出并列出原因。导出文件本身不是持久索引，修改导出文件不会反写 Markdown。

例如上述完整文档导出：

```json
{"go":{"word":"go","translation":"去","example":"She went to school."}}
```

若 `[^w-go]: null` 是有效托管定义，则对应输出为 `{"go":null}`。生成时必须避免以普通对象原型属性作为存储语义；lemma 身份由 `Map` 或无原型键值容器维护。

## 7. 实现验收样例

这些是协议测试输入与预期；对应的共享核心测试位于 `tests/shared/core.test.ts`。覆盖结果和仍待验收的范围见 [路线图](ROADMAP.md)。

| 样例 | 必须成立的结果 |
|---|---|
| `went[^w-go] ... goes[^w-go]` 和一个托管定义 | 两处词形都链接到同一词条；索引只有一条；再次选择已有位置不产生 diff。 |
| 普通 `[^1]`、无定义 `[^w-lost]`、旧 `[^w:go]` | 普通脚注行为保留；无定义者按解析器普通降级，不伪造词条。 |
| `[^w-go]: [1,"x",null]` 或 `[^w-go]: null` | 两者均按合法词条处理，导出保留根类型。 |
| `[^w-go]: {bad}`、`[^w-go]: {} trailing` | 均非词条；若位于区块内，诊断并阻断词条操作，原始行不丢失。 |
| 两条 `[^w-go]: ...`，或两个开始标记 | 诊断精确位置，不挑一条覆盖；拒绝本文件词条写入和导出。 |
| 只在区块外定义 `go`，选择另一处 `go` 存词 | 可查看旧值，但不新建托管同名定义，也不改写区块外行。 |
| `can't`、`mother-in-law`；`go2`、`-go`、`w-Go` | 前两者可作 lemma；后三者不能作为首版词条标签。 |
| 代码块中出现字面 `[^w-go]` | 删除词条不修改代码；仅移除真实引用。 |
| 文档含 CRLF、BOM、重复英文词、粗体或表格中的选区 | 位置映射验证后只补丁目标词后及区块；未触及原文字节不变。无法验证的位置禁用存词。 |
| 保存前外部编辑器改变文件 | 不覆写磁盘；保留草稿并提示冲突。 |
| 设置模板为标量且 `bindings` 用根指针 `""` | 手动确认后可存入该标量；既有定义不被迁移。 |

实现者应将每次词条操作的前后文件做字节级比较：允许变化范围仅为目标引用和托管区块；上述任一情形不能靠全文 Markdown 重新序列化制造“看似正确”的结果。
