# CaretLex 品牌与 Logo 设计基线

> 状态：品牌资产已生成于 `branding/caretlex/`。本文件保留设计约束；浏览器打开预览页和截图检查尚未完成，实测结果见 [品牌 README](../branding/caretlex/README.md) 与 [实施记录](ROADMAP.md)。

CaretLex 是面向英文 Markdown 阅读的本地优先软件，软件界面使用简体中文。Logo 从词条脚注标签 `[^w-lemma]` 提炼出 `[^w-]`：左、右方括号表示 Markdown 语法容器，`^` 是品牌视觉中心，`w-` 标示词条前缀。它必须保持这四部分的顺序与可辨识性，同时是重新绘制的几何图形，不能把普通等宽文本直接当作图标。产品定位和使用场景见 [PRODUCT.md](PRODUCT.md)；实际标签规则以 [PROTOCOL.md](PROTOCOL.md) 为准；实施时序见 [ROADMAP.md](ROADMAP.md)。

## 视觉准则

- 气质：极简、平面、几何、精确、安静，接近成熟开发者工具。不得加入书、放大镜、铅笔、云、数据库或与词条锚点无关的装饰；不用渐变、发光、玻璃效果、3D、纹理和表情符号。
- 主图标是居于正方形画布的横向紧凑 `[^w-]`。两侧方括号采用相同几何骨架并镜像对称，笔画较细；caret 最粗且最醒目；`w-` 的造型清晰、略带代码字体气质。通过笔画、字距和负空间形成独立图形，不能改变字符顺序。
- 以统一的 `128 × 128` 坐标系制作主图标，符号距四边至少保留画布宽度的 10% 作为安全边距。各版本复用相同主图形路径与光学校正值，不靠每份 SVG 分别挪动图形。允许依据视觉重心调整整组符号的位置；不得因此破坏括号对称、裁切或拉伸。
- 方括号、caret、`w-` 的笔端与转角必须遵循同一套克制的几何规则。128px 及以上完整显示 `[^w-]`；在较小尺寸不得把复杂细节机械缩小到模糊。

### 色彩

| 名称 | 色值 | 用途 |
|---|---|---|
| Ink | `#171C26` | 深色底、浅色版主体字形 |
| Slate | `#96A1B2` | 深色版方括号 |
| Paper | `#F4F6F8` | 浅色底、深色版 `w-` 与主体字标 |
| Amber | `#E2B35D` | 深色版 caret 与可选的 `Lex` 字标强调 |
| Amber on light | `#9A6500` | 浅色底上的 caret 与可选的 `Lex` 字标强调 |

深色主标使用 Ink 底、Slate 括号、Amber caret、Paper `w-`；浅色主标使用 Paper 底、Ink 括号与 `w-`、深琥珀 caret。单色版把符号和字标统一为一种前景色，仍须通过形状识别。透明图标不含背景矩形，采用适合浅色底的前景配色；放在深色底时使用对应的深色版或浅色单色版。所有正式 SVG 的颜色以文件内部统一声明的 CSS 自定义属性管理，必要样式自包含，不依赖页面 CSS。

## 字标与组合

字标严格写作 **CaretLex**，不拆词、不改变大小写。使用 Inter 的克制无衬线造型作为制图基础，调整 `Caret`、`Lex` 的字距与图标间距，使它与几何符号在视觉上同重心。深色版 `Caret` 用 Paper，浅色版用 Ink；`Lex` 可分别用 Amber 和深琥珀，但必须保证整词易读。单色版整词与符号同色。

正式发布的横向 SVG 中，字标须转为矢量路径，不通过 `<text>`、外部字体或远程资源渲染。另保留 `logo-wordmark-editable.svg`，以文本形式保存字标、字体名称和编辑参考；该源文件只用于以后调整，不作为无需字体即可独立使用的发布资产。README 应记录最终采用的 Inter 字重、来源和字形转路径步骤。图标与字标使用固定组合比例；横向深浅版以及单色版共享同一版式与路径，只换配色。

## 三个同方向候选

先在一份 `logo-preview.html` 内并列绘制 A、B、C，使用相同的 `128 × 128` 画布、配色和展示尺寸，使比较只反映造型差异。候选图可以嵌入该 HTML；正式交付的是下表中的定稿文件。

| 候选 | 造型重点 | 必须保留 |
|---|---|---|
| A · Protocol | 语法辨认最快，四部分的分隔清楚，caret 略突出，整体紧凑。 | 完整 `[^w-]` 与两括号对称 |
| B · Geometric | 优先优化笔画关系、几何秩序和光学平衡，形成软件品牌标识。 | 完整 `[^w-]` 与 caret 视觉主位 |
| C · Compact | 缩短内部空隙、适度加厚笔画，改善应用图标的缩小表现。 | 完整 `[^w-]`，不能挤成不可辨的色块 |

定稿从 **B** 开始。实际渲染比较后，如果 A 或 C 在视觉平衡及小尺寸辨认上明显更好，可以以它为基础修正；必须在品牌 README 中记下判断依据与最终选择。三种候选都不得替换成书本、字母组合、文件图标等其他概念。

## 验收与平台派生物

制作时实际用浏览器打开预览页并截图检查；若当前环境支持 SVG 渲染，也应检查各独立 SVG。逐项修正视觉重心、括号对称、caret 主次、字标比例、色彩对比、裁切和 16px favicon 的清晰度。预览应在无网络和无字体安装要求的环境中正确显示正式资产。16px 的 `[^]` 简化只限 favicon；128px 及以上应用图标保持完整 `[^w-]`。单色版即使去掉颜色区分，也须能辨认图形顺序。

Linux AppImage 与 deb 所需的 PNG 图标应在定稿后从正式 SVG 确定性生成，并与 `logo-icon-dark.svg` 视觉一致；PNG 是打包派生物，不替代源 SVG。交付前核对 SVG 均可独立打开，预览页离线可用，并在品牌 README 记录修正结果与最终选型。
